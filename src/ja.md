# 共有シングルトンクラス入門：動的なグローバル変数

Nhat Do（4D Inc. テクニカルサービスエンジニア）

テクニカルノート 25-04

## 概要

4Dのプログラミング言語は、開発者により良いコーディング体験を提供するために常に進化を続けています。4D 20 R5では、開発者にできることをさらに広げるために、共有クラス（Shared Class）とシングルトンクラス（Singleton Class）が導入されました。共有クラスを使用すると、独自のプロパティと関数を持つ共有オブジェクトをインスタンス化できます。これをシングルトンクラスと組み合わせると、その共有オブジェクトがすべてのプロセスを通じて唯一のインスタンスであることを保証できます。このテクニカルノートでは、共有シングルトンクラス（Shared Singleton Class）の基礎と、それを使って動的なグローバル変数のストアを効果的に実装する方法について説明します。動的なグローバル変数とは、すべてのプロセスから安全にアクセスおよび変更できる値のことです。

## はじめに

2018年、バージョン17でORDA（Object Relational Data Access）が登場したことにより、4Dのプログラミング言語はパラダイムシフトを迎えました。開発者は、データストア（datastore）と呼ばれる抽象化レイヤーを通じて、オブジェクト記法を使ってアプリケーションのデータにスムーズにアクセスし、変更できるようになりました。しかし、4Dにおける、より洗練されたオブジェクト指向のプログラミングへの流れはそこで終わりませんでした。4D 18 R3のリリースによってクラスを作成できるようになり、開発者は共通の属性と動作を持つ独自のカスタムオブジェクトを定義できるようになりました。これにより、4Dのプログラミング言語においてカプセル化、再利用性、継承の概念が強化されました。とはいえ、クラスの追加は、4Dにおけるオブジェクト指向プログラミングの進化の始まりにすぎませんでした。

4D 20 R5の登場により、共有クラスとシングルトンクラスを作成できるようになりました。共有クラスを使用すると、内容がプロセス間で共有される共有オブジェクトをインスタンス化できます。シングルトンクラスを使用すると、クラスのインスタンス化を単一のインスタンスに制限できます。この2つの概念を組み合わせたものが共有シングルトンクラス、つまり、そのクラスの唯一の共有オブジェクトをインスタンス化できるユーザークラスです。すべてのプロセスを通じてインスタンスが唯一であることが保証されているため、共有シングルトンクラスのインスタンスは、動的なグローバル変数を格納するのに特に便利です。

## 共有オブジェクト、クラス、シングルトン

### 共有オブジェクトとは

共有クラスを理解するには、まず共有オブジェクトの概念を理解しておく必要があります。共有オブジェクトは、通常のオブジェクト型の性質をすべて備えています。任意の数の「プロパティ：値」のペアを格納でき、「OB」コマンドやドット（オブジェクト）記法を使って扱うことができます。ただし、通常のオブジェクトとは異なり、共有オブジェクトにはその内容にプロセス間でアクセスして変更できるという特徴もあります。つまり、プリエンプティブプロセスと互換性があり、スレッドセーフなメソッドを書くのに使用できます。これは、共有オブジェクトを変更する際には「Use...End use」構文が必須となっているためです。たとえば、次のようになります：

```4d
// Method: updateProps
#DECLARE($mySharedObj : Object; $prop1 : Text; $val1 : Variant; $prop2 : Text; $val2 : Variant)

Use ($mySharedObj)
    $mySharedObj[$prop1]:=$val1
    $mySharedObj[$prop2]:=$val2
End use
```

上の例の「updateProps」は、「New process」コマンドや「CALL WORKER」コマンドを使って呼び出すことができるメソッドです。引数「$mySharedObj」は共有オブジェクトで、ほかのいくつかの引数とともに「updateProps」に渡されます。このメソッドでは、「Use/End use」キーワードで保護することにより「$mySharedObj」を安全に変更しています。「Use」の間、このオブジェクトはロックされ、ほかのプロセスから変更することはできません。共有オブジェクトは、「New shared object」コマンドを使って作成するか、共有クラスからインスタンス化することができます。

### 共有クラスの役割

共有クラスは、通常のクラスと同じようにクラスコンストラクターを持ちますが、その前に「shared」キーワードが付きます。これは、共有クラスに対して「new()」関数を呼び出して作成されるインスタンスがすべて共有オブジェクトになることを意味します。「New shared object」コマンドで作成した共有オブジェクトとは異なり、共有クラスからインスタンス化したオブジェクトでは、クラス関数を使用できるという利点があります。関数の中で「This」コマンドを介して共有クラスのオブジェクトを変更する必要がある場合、「This」は共有オブジェクトを参照しているため、「Use/End use」キーワードを使用する必要があります。たとえば、次のようになります：

```4d
// Class: MySharedClass
shared Class constructor($prop : Text)
    This.prop:=$prop

Function add($foo : Text)
    Use (This)
        This.prop+=$foo
    End use
```

上の例では、共有クラス「MySharedClass」の「add」関数が、「This」に対するドット記法で共有オブジェクトの「prop」プロパティを変更しています。そのため、「Use...End use」構文を使って「This」を保護する必要があります。しかし、共有クラスでは「Function」キーワードの前に「shared」キーワードを付けることで、「Use/End use」キーワードを完全に省略できます。たとえば、上の「MySharedClass」の「add」関数は次のように書き換えることができます：

```4d
shared Function add($foo : Text)
    This.prop+=$foo
```

つまり、この場合の「shared」キーワードは、クラス関数の中で共有クラスの共有オブジェクト（「This」）を変更するたびに「Use...End use」を書く必要をなくすための、シンタックスシュガーとして機能します。これにより、共有クラスのオブジェクトを中心としたコードを、より速く書けるようになり、読みやすくもなります。最近導入された特別な種類のユーザークラスは、共有クラスだけではありません。ユーザークラスは、共有クラスのほかに、シングルトンクラスとして指定することもできます。

### シングルトンクラスの仕組み

シングルトンクラスは、クラスコンストラクターの前に付ける「singleton」キーワードで示されます。その名のとおり、シングルトンクラスのインスタンスは（生成元のプロセスにつき）同時に1つしか存在できません。シングルトンは、シングルトンクラスの「.new()」メソッドを呼び出すか、シングルトンの「.me」プロパティを呼び出すことでインスタンス化できます。シングルトンがまだインスタンス化されていない場合、「.me」プロパティを呼び出すことは、引数なしで「.new()」を呼び出すことと同じです。インスタンス化された後は、「.me」を呼び出すと、そのシングルトンのインスタンスが返されるだけです。たとえば、「MySingletonClass」という名前の次のようなシングルトンクラスがあるとします：

```4d
// Class: MySingletonClass
singleton Class constructor($param : Text)
    This.foo:=$param
```

MySingletonClassのインスタンスは、次のようなコードを実行して作成するか：

```4d
$mySingleton:=cs.MySingletonClass.new("bar")
```

あるいは、次のように「.me」プロパティを呼び出して作成することができます：

```4d
$mySingleton:=cs.MySingletonClass.me
```

最初に、次のように両方が続けて呼び出された場合：

```4d
$mySingleton1:=cs.MySingletonClass.me
$mySingleton2:=cs.MySingletonClass.new("bar")
// cs.MySingletonClass.me.foo = ""
```

常に先に呼び出されたほうが優先されます。つまり、上の例では、シングルトンインスタンスの「foo」プロパティは「bar」ではなく、空の文字列（""）になります。さらに、その後シングルトンに加えた変更は、次の例のように両方の変数に反映されます：

```4d
cs.MySingletonClass.me.foo:="baz"
cs.MySingletonClass.me.qux:="plugh"
// $mySingleton1.foo = "baz", $mySingleton1.qux = "plugh"
// $mySingleton2.foo = "baz", $mySingleton2.qux = "plugh"
```

このように、シングルトンクラスは、特定のプロセス内でインスタンスが2回以上作成されるのを防ぎ、その値を1か所に集約します。では、すべてのプロセスで共通のシングルトンが必要な場合はどうすればよいでしょうか。そこで登場するのが共有シングルトンクラスです。

**注：** 基本の（プロセス）シングルトンクラスと共有シングルトンクラスのほかに、セッションシングルトンクラスという種類もありますが、このテクニカルノートでは取り上げません。

### 共有シングルトンクラス

共有シングルトンクラスを作成するには、クラスコンストラクターの前にある「singleton」キーワードの前に、「shared」キーワードを付けるだけです。たとえば、次のようになります：

```4d
// Class: MySharedSingletonClass
shared singleton Class constructor($foo : Text)
    This.foo:=$foo

shared Function myMethod($bar : Text)
    This.bar:=$bar
```

この種類のユーザークラスでは、シングルトンとしても機能する、クラスの共有オブジェクトをインスタンス化できます。上の例では、「MySharedSingletonClass」を「.new()」または「.me」の呼び出しでインスタンス化すると、そのクラスの唯一のインスタンスである共有オブジェクトが作成されます。共有シングルトンクラスは、いわば両者の長所を兼ね備えています。すなわち、共有関数を利用でき、プロセス間で共有できるオブジェクトをインスタンス化できること、そしてその存在を単一のソースに限定できることです。これは、動的なグローバル変数のストアを実装する場合に特に便利です。このような値はプロセス間で共有・更新する必要があり、また、信頼できる唯一の情報源（Single Source of Truth）があることで、管理や保守が容易になるからです。

## 動的なグローバル変数

### 概要と背景

多くのアプリケーションでは、**グローバル**にアクセスでき、値が**動的**に変化する**変数**を保持することは珍しくありません。動的なグローバル変数の一般的な用途としては、アプリケーション全体の設定の管理、セッションやユーザーの状態の保存、キャッシュやメモ化などが挙げられます。特に4Dのプログラミングでは、複数のフォームを並行するプロセスで開く場合など、変数を複数のプロセス間で共有・更新しなければならないことがあります。4Dで動的なグローバル変数を実装する方法はいくつかあります。このテクニカルノートでは、その中で最も新しく実用的な手法の1つである、共有シングルトンクラスを使用する方法について説明します。

これまで、動的なグローバル変数を扱う主な手法は、インタープロセス変数を使用することでした。しかし、4Dの技術が進歩するにつれて、インタープロセス変数は非推奨となりました。その主な理由は、インタープロセス変数がプリエンプティブプロセスから使用できないことです。つまり、インタープロセス変数を使ってスレッドセーフなメソッドを書くことはできません。マルチコアのコンピューターでマルチスレッド対応のアプリケーションを実行することが広く普及している現在では、インタープロセス変数に代わる手法が必要です。

幸いなことに、現在では、共有シングルトンクラスを使って動的なグローバル変数を扱う4Dアプリケーションを開発できます。この種類のクラスのインスタンスは実質的に共有オブジェクトなので、プリエンプティブプロセスと互換性があるという利点があります。さらに、シングルトンであるため、異なるプロセスが誤って複数の情報源を生み出してしまうことを防げます。共有シングルトンクラスには、共有関数を使用できるという利点もあり、そこに追加の機能を組み込むこともできます。

### クラスの実装

面倒な処理のほとんどは4Dの内部ですでに行われているため、動的なグローバル変数のための共有シングルトンクラスの実装を始めるのはとても簡単です。また、いつでも機能を追加して拡張することができます。最低限必要なのは、次のようなクラスコンストラクターだけです：

```4d
// Class: GlobalVars
shared singleton Class constructor
```

上の例では、クラスコンストラクターと「shared singleton」キーワードだけで、共有シングルトンクラス「GlobalVars」を作成しています。グローバル変数のためのクラスを作るのに本当に必要なのは、これだけです。あとは、「GlobalVars」を次のように使用できます：

```4d
var $globals:=cs.GlobalVars.me

Use ($globals)
    $globals.foo:="bar"
End use
```

上の例では、シングルトンをインスタンス化してから、グローバル変数「foo」に値「bar」を代入しています。この変数は、シングルトンオブジェクトのプロパティとして作成されます。これで、「foo」の値にアクセスする必要があるときは、どのプロセスからでも「cs.GlobalVars.me.foo」から読み取ることができます。なお、「cs.GlobalVars.me」をローカル変数「$globals」に代入しておくと、コードを少し速く書くことができます。

もちろん、ほかのクラスと同じように、コンストラクターが引数を受け取って独自の内部プロパティを初期化するようにすることもできます：

```4d
// Class: GlobalVars
shared singleton Class constructor($foo : Text)
    This.foo:=$foo
```

こうすると、シングルトンをインスタンス化すると同時にグローバル変数を設定できます：

```4d
var $globals:=cs.GlobalVars.new("bar") // cs.GlobalVars.me.foo = "bar"
// assign new variable “num”
Use ($globals)
    $globals.num:=123
End use
```

グローバル変数に代入するたびに「Use...End use」構文をすべて書くのは面倒だと思いませんか。もっと簡単にできるように、「assign」というクラスの共有関数を作成してみましょう：

```4d
// Class: GlobalVars
shared Function assign($name : Text; $value : Variant)
    This[$name]:=$value
```

これで、シングルトンの共有関数「assign」を使ってグローバル変数に値を設定できるようになり、「Use/End use」キーワードが不要になります：

```4d
$globals.assign("num"; 123) // cs.GlobalVars.me.num = 123
```

グローバル変数を更新する必要があるときは、変数名と新しい値を渡してこの関数を呼び出すだけです：

```4d
$globals.assign("num"; 456) // cs.GlobalVars.me.num = 456
```

**注：** これは、グローバル変数に代入する値がスカラー値である場合には常に有効です。共有シングルトンにはコレクションやオブジェクトも格納できますが、それらは共有コレクションや共有オブジェクトとして注意して扱う必要があります。コレクションやオブジェクトのグローバル値を管理する方法については、このテクニカルノートの「デモアプリケーション」の節で詳しく説明します。

以上で、共有シングルトンクラスを使った動的なグローバル変数の基本的な実装は完成です。しかし、開発者の使い勝手を良くするために追加できることはまだたくさんあります。たとえば、既存のグローバル変数を更新するたびに型の検証を行い、新しい値のデータ型が既存の値のデータ型と同じであることを確認したいとします。これを実装するには、「assign」関数を次のように変更します：

```4d
// Class: GlobalVars
shared Function assign($name : Text; $value : Variant)
    // new variable
    If (Undefined(This[$name]))
        This[$name]:=$value
    Else
        // validates input type on existing variable
        If (Value type(This[$name])=Value type($value))
            This[$name]:=$value
        Else
            ALERT("Wrong input type for existing variable: "+$name)
        End if
    End if
```

ここで、上の例の「num」変数に次のように再代入しようとすると：

```4d
$globals.assign("num"; "789")
// ALERT - Wrong input type for existing variable: num
```

その試みは失敗し、開発者に警告が表示されます。これは、作成した変数のデータ型が予期せず変わらないようにするのに役立ち、後々のデバッグの手間を防ぐことができます。型の検証のほかにも、動的なグローバル変数のクラスの実装を改善する方法はたくさんあります。次の節（「スカラーの例」を参照）で紹介するのはその1つで、可変長引数を使って、複数のグローバル変数への代入を1行でまとめて行えるようにするものです。

## デモアプリケーション

この節では、このテクニカルノートに付属するデモアプリケーションについて補足します。テーマの性質上、「GlobalVars」クラスの動作は主にデバッガーで式を確認することによって示しています。デモアプリケーションは、4D 20 R5以降で開いてください。

### 起動時の例

この例では、環境から取得した値を共有シングルトンクラスのグローバル変数として初期化する方法を示しています。アプリケーションの起動時に、Resourcesフォルダーにある「info.txt」ファイルのJSONから取得した値で、「GlobalVars」シングルトンがインスタンス化されます：

```4d
// Method: __init_vars_from_env
var $file:=File("/RESOURCES/info.txt")
cs.GlobalVars.new($file)
```

その後、それぞれの値がシングルトンから読み取られ、別のメソッドによってウェルカムメッセージに表示されます。JSONの値を変更してアプリケーションを再起動し、グローバル変数の初期値がどのように変わるかを確認してみてください。

### スカラーの例

「_create_vals」メソッドを実行して、スカラー値を持つグローバル変数がどのように管理されるかを確認してください。「assign」関数では、次のように引数の間接参照の構文を使って可変長引数を処理していることに注目してください：

```4d
// Class: GlobalVars, Function: assign
    For ($i; 1; Count parameters; 2)
            This[${$i}]:=${$i+1}
    End for
```

これにより、複数の値を1行でグローバル変数に代入できます：

```4d
// Method: _create_vals
$globals.assign("foo"; 123; "bar"; "hello"; "bool"; False)
```

デバッガーをステップ実行しながら式エリアで「$globals」式を監視し、スカラーのグローバル変数が異なるプロセスでどのように作成・更新されるかを確認してください。たとえば、「update_vals」プロセスが終了する前に「_create_vals」プロセスをステップ実行すると、異なる結果が得られます。

### オブジェクトの例

この例では、オブジェクト値をグローバル変数として扱う方法を示しています。「_build_car」メソッドでは、新しい車のオブジェクトを共有オブジェクトとして作成しています。これは、「GlobalVars」シングルトンのような共有オブジェクトは、プロパティの値として共有でないオブジェクトをサポートしていないためです：

```4d
// Method: _build_car
var $new_car:=New shared object("make"; "Fiat"; "model"; "Panda")
$globals.assign("car_obj"; $new_car)
```

車のオブジェクトのプロパティを更新するときは、それが共有オブジェクトであるため、「Use/End use」キーワードが必要です：

```4d
// Method: _mod_car
$car:=$globals.car_obj
Use ($car)
    $car[$prop]:=$val
End use
```

「assign」関数の「shared」キーワードが適用されるのは親の共有オブジェクト（「This」）だけです。子の共有オブジェクトを変更するときに「Use...End use」を省略することはできません。

### コレクションの例

この例では、コレクション値をグローバル変数として管理する方法を示しています。オブジェクト値と同様に、コレクション値を共有シングルトンのプロパティ値として代入するには、共有コレクションとして作成する必要があります：

```4d
// Method: _pick_fruits
var $new_basket:=New shared collection("apple"; "orange")
$globals.assign("fruits_coll"; $new_basket)
```

ただし、共有コレクションを変更するコレクション関数は内部で自動的に「Use...End use」を実行するため、この方法でコレクションのグローバル変数を更新する場合は、明示的に書く必要はありません：

```4d
// Method: _pick_fruits
$fruits:=$globals.fruits_coll
$fruits.push("cherry")
```
